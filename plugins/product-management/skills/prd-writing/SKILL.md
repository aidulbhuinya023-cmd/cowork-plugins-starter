# PRD Writing

## Steps

1. Read `product-management-team-context` for the PRD template, metric conventions, and review process.
2. Gather inputs where connected:
   - Problem evidence from ~~customer feedback and ~~product analytics
   - Existing designs from ~~design
   - Related tickets from ~~project tracker
   - Prior decisions from ~~knowledge base
3. Draft the PRD with these sections: problem and who has it, evidence, goals and non-goals, success metrics (baseline, target, how measured), prioritized requirements (must, should, could), design links, risks and dependencies, rollout plan, open questions.
4. Put **open questions** and **assumptions** at the top so the owner sees them first.

Label every assumption as an assumption. Never invent metrics or baselines. Write "needs data" instead.
